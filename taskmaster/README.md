# TaskMaster

TaskMaster - это учебный Django-проект: планировщик задач с регистрацией пользователей, категориями, статистикой, достижениями, магазином, темами оформления и питомцем-котиком.

Проект можно воспринимать как обычный сайт на Django. Пользователь заходит в браузере, создает задачи, выполняет их, получает опыт, монеты и достижения.

## 1. Как запустить проект

### Что нужно установить заранее

Нужно, чтобы на компьютере были:

- Python 3.11 или новее;
- Git;
- Redis, если хочешь запускать фоновые задачи Celery;
- Docker, если Redis будешь запускать через Docker.

Redis нужен только для фоновых задач: сброса серии и email-напоминаний. Сам сайт можно запустить и без Redis.

### 1. Склонировать проект

```powershell
git clone https://github.com/USERNAME/REPOSITORY.git
cd TaskManager
```

Если проект уже скачан, просто перейди в папку проекта:

```powershell
cd C:\Users\lazma\projects\TaskManager
```

### 2. Создать виртуальное окружение

Виртуальное окружение - это отдельная папка с Python-библиотеками только для этого проекта.

```powershell
python -m venv venv
```

Активировать окружение на Windows:

```powershell
.\venv\Scripts\Activate.ps1
```

Если PowerShell запрещает запуск скриптов, выполни:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

После активации в начале строки терминала должно появиться что-то вроде:

```text
(venv)
```

### 3. Перейти в папку Django-проекта

Файл `manage.py` лежит внутри папки `taskmaster`, поэтому команды Django нужно выполнять оттуда.

```powershell
cd taskmaster
```

### 4. Установить зависимости

```powershell
pip install -r requirements.txt
```

Зависимости - это библиотеки, которые нужны проекту: Django, Celery, Redis-клиент и другие.

### 5. Создать файл настроек `.env`

В проекте есть пример файла:

```powershell
copy .env.example .env
```

В учебном запуске можно ничего не менять: в `settings.py` уже есть значения по умолчанию. Для реального сайта нужно поменять `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS` и email-настройки.

### 6. Применить миграции

Миграции создают таблицы в базе данных.

```powershell
python manage.py migrate
```

По умолчанию используется SQLite. База будет лежать в файле:

```text
taskmaster/db.sqlite3
```

Этот файл не нужно отправлять в GitHub.

### 7. Загрузить начальные данные

Начальные данные лежат в файле `initial_data.json`. Там находятся достижения, темы, товары магазина, аксессуары и расцветки котика.

```powershell
python manage.py loaddata initial_data.json
```

### 8. Создать администратора

```powershell
python manage.py createsuperuser
```

После этого можно зайти в админку:

```text
http://127.0.0.1:8000/admin/
```

### 9. Запустить сайт

```powershell
python manage.py runserver
```

Открыть в браузере:

```text
http://127.0.0.1:8000/
```

## 2. Запуск фоновых задач

Этот раздел нужен, если ты хочешь, чтобы работали автоматические процессы:

- сброс серии, если пользователь пропустил день;
- email-напоминания о незавершенных задачах.

Для обычной проверки сайта этот раздел можно пропустить.

### Запустить Redis через Docker

```powershell
docker run -d -p 6379:6379 redis:alpine
```

### Запустить Celery Worker

Открой второй терминал, активируй `venv`, перейди в `taskmaster` и выполни:

```powershell
celery -A config worker --loglevel=info
```

Worker - это процесс, который выполняет фоновые задачи.

### Запустить Celery Beat

Открой третий терминал, активируй `venv`, перейди в `taskmaster` и выполни:

```powershell
celery -A config beat --loglevel=info
```

Beat - это планировщик. Он решает, когда запускать фоновые задачи.

## 3. Если проект не запускается

### Не найден Python

Проверь:

```powershell
python --version
```

Если команда не работает, нужно установить Python и добавить его в `PATH`.

### Не активируется виртуальное окружение

Попробуй:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

### Сломалось виртуальное окружение

Иногда папку `venv` проще удалить и создать заново:

```powershell
cd C:\Users\lazma\projects\TaskManager
Remove-Item -Recurse -Force .\venv
python -m venv venv
.\venv\Scripts\Activate.ps1
cd taskmaster
pip install -r requirements.txt
```

### Не видны новые товары, темы или достижения

Выполни:

```powershell
python manage.py loaddata initial_data.json
```

### Изменилась модель, но база ругается

Выполни:

```powershell
python manage.py migrate
```

## 4. Главная идея проекта

TaskMaster - это планировщик задач, который превращает выполнение дел в маленькую игру.

Пользователь:

- регистрируется или входит в аккаунт;
- создает задачи;
- делит задачи по категориям;
- выполняет задачи;
- получает опыт и монеты;
- открывает достижения;
- покупает темы, аксессуары и расцветки котика;
- следит за статистикой.

Главная мотивация: чем стабильнее пользователь выполняет задачи, тем сильнее прокачивается профиль и тем счастливее выглядит котик.

### `manage.py`

Главный файл для команд Django.

Примеры:

```powershell
python manage.py runserver
python manage.py migrate
python manage.py createsuperuser
```

### `requirements.txt`

Список библиотек проекта.

Когда ты выполняешь:

```powershell
pip install -r requirements.txt
```

Python устанавливает все библиотеки из этого файла.

### `initial_data.json`

Файл с начальными данными.

В нем лежат:

- достижения;
- темы магазина;
- щиты серии;
- аксессуары котика;

Папка с настройками всего Django-проекта.

### `apps/`

Папка с приложениями проекта. В Django приложение - это отдельная часть сайта. Например, задачи отдельно, магазин отдельно, аккаунты отдельно.

### `templates/`

HTML-шаблоны. Это файлы, которые отвечают за внешний вид страниц.

Например:

- `templates/base.html` - общий каркас сайта;
- `templates/tasks/task_list.html` - страница задач;
- `templates/shop/shop.html` - магазин;
- `templates/accounts/profile.html` - профиль;
- `templates/stats/stats.html` - статистика;
- `templates/gamification/achievements.html` - достижения.

### `static/`

Статические файлы:

- CSS;
- JavaScript;
- темы оформления.

## 6. Как Django обрабатывает страницу

Упрощенно сайт работает так:

1. Пользователь открывает ссылку в браузере.
2. Django смотрит в `urls.py`, какой код должен отвечать за эту ссылку.
3. View получает данные из базы.
4. View передает данные в HTML-шаблон.
5. Django собирает HTML-страницу.
6. Браузер показывает страницу пользователю.

Например:

```text
/tasks/
```

ведет в приложение `apps/tasks`, там вызывается `TaskListView`, который получает задачи пользователя и показывает шаблон `task_list.html`.

## 7. Приложение `accounts`

Путь:

```text
apps/accounts/
```

Это приложение отвечает за пользователей.

### Модель `User`

Обычный пользователь Django расширен дополнительными полями:

- `level` - уровень;
- `xp` - текущий опыт;
- `coins` - монеты;
- `streak` - текущая серия дней;
- `max_streak` - лучшая серия;
- `last_activity_date` - дата последней активности;
- `streak_shields` - количество щитов серии;
- `theme` - выбранная тема сайта;
- `pet_accessory` - выбранный аксессуар котика;
- `pet_color` - выбранная расцветка котика.

### Методы пользователя

В модели есть методы, которые похожи на обычные функции, только принадлежат пользователю.

Например:

- `add_xp(amount)` - добавить опыт;
- `add_coins(amount)` - добавить монеты;
- `spend_coins(amount)` - потратить монеты;
- `update_streak()` - обновить серию;
- `get_pet_state()` - узнать состояние котика;
- `get_theme_css()` - узнать CSS-класс темы.

### Профиль

Профиль находится по адресу:

```text
/accounts/profile/
```

Там показываются:

- данные пользователя;
- уровень и опыт;
- монеты;
- серия;
- котик;
- инвентарь;
- полученные достижения.

## 8. Приложение `tasks`

Путь:

```text
apps/tasks/
```

Это основная часть проекта. Здесь находятся задачи и категории.

### Модель `Task`

Задача хранит:

- название;
- описание;
- тип задачи;
- приоритет;
- сложность;
- категорию;
- дату выполнения;
- выполнена задача или нет;
- дату завершения.

### Типы задач

В проекте есть такие типы:

- ежедневная;
- разовая;
- повторяющаяся;
- долгосрочная цель.

### Сложность задачи

От сложности зависит награда:

| Сложность | XP | Монеты |
|---|---:|---:|
| Легкая | 10 | 5 |
| Средняя | 25 | 10 |
| Сложная | 50 | 20 |
| Очень сложная | 100 | 40 |

### Что происходит при выполнении задачи

Когда пользователь нажимает на выполнение задачи:

1. Задача получает `is_completed = True`.
2. Записывается время завершения.
3. Пользователь получает XP.
4. Пользователь получает монеты.
5. Обновляется серия.
6. Проверяются достижения.
7. Интерфейс обновляет счетчики в верхнем меню.

Главная логика находится в методе:

```text
Task.complete()
```

### Категории

Категории нужны, чтобы группировать задачи.

Категория хранит:

- пользователя;
- название;
- цвет;
- иконку папки.

В интерфейсе пользователь редактирует только название и цвет. Иконка папки ставится автоматически.

## 9. Приложение `gamification`

Путь:

```text
apps/gamification/
```

Это приложение отвечает за достижения и игровые механики.

### Достижения

Достижение хранит:

- название;
- описание;
- иконку;
- тип условия;
- значение условия;
- награду XP;
- награду монетами.

Примеры условий:

- выполнить 1 задачу;
- выполнить 10 задач;
- достичь серии 7 дней;
- достичь 5 уровня.

### Как проверяются достижения

Файл:

```text
apps/gamification/services.py
```

Главная функция:

```python
check_achievements(user)
```

Она смотрит на пользователя и проверяет, какие достижения он уже заслужил.

Например, если у пользователя есть 1 выполненная задача, то откроется достижение "Первый шаг".

Проверка вызывается:

- после выполнения задачи;
- при открытии страницы достижений.

Это сделано, чтобы старые выполненные задачи тоже могли засчитать достижение.

## 10. Приложение `shop`

Путь:

```text
apps/shop/
```

Магазин нужен, чтобы пользователь тратил монеты.

### Модель `ShopItem`

Товар магазина хранит:

- название;
- описание;
- тип товара;
- цену;
- изображение, если оно есть;
- CSS-класс;
- активен ли товар;
- доступен ли товар по умолчанию.

### Типы товаров

В проекте используются:

- `theme` - тема сайта;
- `shield` - щит серии;
- `pet_accessory` - аксессуар котика;
- `pet_color` - расцветка котика.

### Модель `UserInventory`

Это инвентарь пользователя. Она связывает пользователя и купленный товар.

Если пользователь купил "Красный шарфик", в `UserInventory` появится запись:

```text
этот пользователь владеет этим товаром
```

### Как работает покупка

Когда пользователь покупает товар:

1. Django проверяет, хватает ли монет.
2. Если монет не хватает, покупка не проходит.
3. Если монет хватает, монеты списываются.
4. Товар добавляется в инвентарь.
5. Пользователь может применить товар в профиле.

Щиты серии работают немного иначе: их можно покупать много раз, потому что это расходуемый предмет.

## 11. Котик

Котик - это визуальная мотивация пользователя.

Он показывается:

- в углу сайта;
- в профиле;
- в магазине как превью аксессуаров и расцветок.

### Состояния котика

Состояние зависит от серии:

| Серия | Состояние |
|---:|---|
| 0-2 дня | спит |
| 3-6 дней | обычный |
| 7+ дней | счастливый, сияет и парит |

Если серия сброшена, котик грустит один день.

### Аксессуары

Аксессуары покупаются в магазине за монеты.

Примеры:

- шапка;
- колокольчик;
- шарфик;
- крылья.

### Расцветки

Расцветки тоже покупаются за монеты, но стоят намного дороже. Это сделано специально, чтобы цвет котика был заметным достижением.

Примеры:

- кремовый окрас;
- полночный окрас;
- снежный окрас;
- тигровый окрас;
- лунный окрас.

## 13. Темы сайта

Тема сайта - это CSS-класс, который добавляется к тегу `body`.

Пример:

```html
<body class="theme-dark">
```

В `base.html` описаны CSS-переменные для тем:

- `theme-dark`;
- `theme-default`;
- `theme-sunset`;
- `theme-forest`.

Пользователь покупает тему в магазине, а потом применяет ее в профиле.

Если тема не выбрана, используется темная тема.

templates/base.html

Это главный HTML-шаблон. От него наследуются остальные страницы.

## 16. Email-напоминания

По умолчанию письма не отправляются реально, а выводятся в консоль. Это удобно для разработки.

Настройка находится в `settings.py`:

```python
EMAIL_BACKEND = 'django.core.mail.backends.console.EmailBackend'
```

Для реальной отправки нужно заполнить `.env`, например:

```text
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your@gmail.com
EMAIL_HOST_PASSWORD=app-password
```
